# mGBA testing notes

mGBA SDL and Xvfb/xdotool are part of the standard development container. The Debian package in this workspace is mGBA 0.10.1; upstream 0.10.5 is also available for local experiments. mGBA can execute GBA video modes, OBJ/OAM, DMA and input, and its debugger can inspect emulated CPU/memory. Its command line accepts `--bios FILE` (`-b`). A BIOS is not stored in the repository/container; if one is supplied for local testing, keep it outside the checkout and out of releases. See the [mGBA command-line options](https://github.com/mgba-emu/mgba/blob/master/src/feature/commandline.c).

Opaque, unscaled artwork now uses the GBA's DMA3 for each framebuffer row. DST1-marked artwork retains CPU compositing to preserve transparent pixels; scaled vertical previews also use CPU sampling because GBA DMA has no scaling mode. mGBA can validate these execution paths, but physical timing still matters on the SuperCard bus.

The full `superfw-*.fw` image boots far enough to display its SuperFW splash in mGBA, then cannot initialize the SuperCard SD/Chis/Lite storage interface. mGBA does not emulate those cartridge protocols, nor their SD, NOR or cartridge SDRAM. It therefore cannot validate the real kernel's browser or card timing by itself. Do not call splash/boot execution a menu test.

`scripts/build-browser-preview.sh` builds `build/mgba/browser-preview.gba` and generates disposable data in `build/mgba/fixtures/`. The data contains three synthetic 32 KiB GBA files with header game codes at `0xAC`, matching filename Box BMPs, and Title BMPs in the nested EZ-FLASH code layout. The fixture ROMs have no Nintendo boot logo/code and are intentionally non-launchable. The preview embeds their headers and BMPs, uses the real artwork decoder/blitter, and links the same carousel layout/motion functions used by the kernel. Run `bash scripts/test-browser-preview-mgba.sh` for an Xvfb smoke check: it prints the emulator version, builds the ROM, captures F12, and verifies a known synthetic Title-art color is visible. Debian mGBA 0.10.1 at `/usr/games/mgba` passed this check on 2026-11-14. Box art and key-driven navigation/orientation are not yet visually confirmed; host adapter/artwork tests cover data and path handling. Earlier upstream 0.10.5 AppImage attempts showed a blank frame, so use and record the package/version that actually ran. This harness does not mount the generated FAT tree or boot the full SuperFW firmware. It validates only shared GBA renderer/artwork code. Physical cards remain required for SD latency, NOR behavior, save timing and final UI qualification.

Do not add a BIOS dump to the repository. If a later boot-path test genuinely needs the BIOS, use a lawful dump supplied by the owner; otherwise continue with the BIOS-free renderer harness.

Latest correction: the preview uses hidden-page drawing and a VBlank page switch. The former orange marker was a UI fill, so the smoke check now excludes all four UI colors and requires decoded BMP colors. Horizontal Title and vertical Box pass this stronger check. Set `PREVIEW_VERTICAL=1 PREVIEW_BOX=1` before the smoke command to select vertical Box deterministically; defaults are horizontal Title. This avoids relying on unconfirmed emulator keyboard bindings.

Run `PREVIEW_MATRIX=1 bash scripts/test-browser-preview-mgba.sh` to check all four horizontal/vertical and Title/Box combinations. Generated `view-0-0.png`, `view-0-1.png`, `view-1-0.png`, `view-1-1.png` preserve the latest screenshots in ignored build output. All four initial views rendered decoded BMP colors in mGBA 0.10.1. This does not validate interactive transitions or storage lookup.

The preview now links the production font renderer and extracts the actual draw_text_ovf_rotate helper from menu.c during its build, so selected filenames exercise the real text path. It supplies an empty supplemental font database and uses the embedded ASCII font for synthetic names. Build flag `-Wno-old-style-declaration` suppresses the existing const-static ordering warning in fonts/hangul.h; other warnings remain errors. Vertical Title screenshot with text was visually inspected in mGBA 0.10.1. This still does not render whole production settings/game/system screens.

`PREVIEW_OFFSET=128` freezes a midpoint transition for visual inspection; negative values cover the opposite direction. `PREVIEW_AUTOMOVE=1` automatically retargets selection every 120 rendered frames through the shared motion functions. The filename now follows the layout's visually focused item, matching production. Vertical midpoint and automatic-motion smoke checks passed with mGBA 0.10.1; a screenshot alone does not measure frame pacing or prove keyboard navigation.

`PREVIEW_SCREEN=1 bash scripts/test-browser-preview-mgba.sh` renders the actual production Tools function with its generated English messages and real font helpers. The five common tool rows are included; Chis NOR-only row is not part of this fixture. The preview stubs selection OAM submission and never invokes tool actions. mGBA 0.10.1 screenshot passed (2312 body text pixels), and all five rows were visually inspected without clipping. This is layout evidence only.

`PREVIEW_TIMING=1` measures render() using CPU-clock Timer0 cascaded into Timer1 and prints cycles in the footer before page flip. Timer instrumentation exists only in the preview. With the optimized horizontal sample map, vertical Title reported 1,364,130 cycles in mGBA 0.10.1 (about4.86 GBA frame periods of280896cycles). This includes schematic card/text/background drawing and three embedded images, excludes timer readout/page wait, and uses internal-RAM fixtures rather than SuperCard SDRAM/SD. It demonstrates that this isolated redraw path is still too expensive for fluid animation; it does not measure card speed. Next optimize repeated resampling/redrawing and compare identical scenes.

`PREVIEW_ANIMATION=0` exercises the native-size selected-art preview with extracted production Title/Box placeholders for neighbors. The vertical Box screenshot was visually inspected (5731 BMP-color pixels); timer footer reported1051587cycles for this fixture. This differs from the earlier Title scene and is not a like-for-like performance comparison. Off removes scaling, but framebuffer fill, font and artwork copying/compositing still cost CPU time. Real production-frame/card responsiveness remains unmeasured.
